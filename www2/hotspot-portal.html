Custom CSS
Restyle the portal with your own CSS. It is added after the built-in styles, so it can only ever affect the look — it can't touch coin, voucher or login logic. Mistakes are caught for you: invalid CSS (an unclosed {, an @import or outside url()) is refused, and if your styles ever hide the voucher box, Insert Coin or a pop-up button, customers' phones automatically fall back to the stock look. This admin page is never styled by it.
Tips & colour variables
If a change has no effect, add !important. Many built-in rules (card background and radius, button shape and padding…) use it, e.g. border-radius: 24px !important;. Colour variables never need it.
Colours live in variables. The portal is built on them, so changing a variable recolours everything that uses it. Dark is the default: :root { … }. Light mode needs its own block: :root[data-theme="light"] { … }. Use the Dark/Light switch on the preview to check both.
Variables: --bg-body page · --bg-surface card · --bg-surface-hover header · --bg-input inputs · --text-primary · --text-secondary · --border-color · --accent-color · --btn-primary-bg|border|color (and -hover-bg|border) · --btn-coin-* Insert Coin · --btn-rates-* WiFi Rates · --btn-danger-* Pause · --btn-done-* Done · --coin-sym-color / --coin-val-color coin amount.
Images: only the portal's own files work — url(/img/promo1.png), url(/img/portal_logo.png) (upload them in the sections above) or an inline data:image/.... Fonts and anything on the internet are blocked on purpose: customers aren't online yet, so an external file would stall the portal.
Locked yourself out on your phone? Open the portal address with ?nocss=1 on the end to see the stock look, then fix the CSS here. A browser tab that already switched your CSS off keeps the stock look until it is closed and reopened.
